# Phase 07：本地游玩统计

> 状态：功能实现完成，待实机视觉验收  
> 分支：`feature/local-game-statistics`  
> 范围：单人每日/随机与多人房间对局  
> 数据边界：统计数据仅保存在玩家浏览器，不新增服务端统计表或云同步

## 1. 指标口径

- 单人一次已结束 session 计一次游玩；多人一次已结束 match 计一次游玩，BO3/BO5/BO7 不按 round 重复计数。
- 单人成功为 session `won`；多人成功为观察者视角 match `win`。平局单列，放弃、断线判负和重开废弃均进入失败结果。
- 作品、获胜猜测次数和可比较耗时以题局为单位：单人 session 为一题局，多人的每个 round 为一题局。
- 作品图灰柱为答案作品出现次数，主题色柱为本地玩家获胜题局数，折线为该作品胜率。横轴统一使用 `THxx`，tooltip 显示总题局、获胜题局与胜率。
- 有效耗时只累计页面可见且题局为 `playing` 的前台时间。单次猜测在提交动作发生时截点，不计 API 往返；整场多人耗时为各 round 有效耗时之和。
- 未能在房间保留期内恢复终态的多人草稿标记为“同步不完整”，不参与胜率、作品和耗时聚合。

## 2. IndexedDB 模型

使用 Dexie 管理 `touhouflandre-stats`：

- `records`：完成的 `SingleStatsRecord | MultiplayerStatsRecord`。角色、作品、头像与猜测序列保存当时快照。
- `drafts`：进行中的单人 session 或多人 match；多人按 `round.ended` 幂等追加题局，并在 `match.ended` 到达时事务化转为记录。
- `metadata`：schema 版本、`clearedAt` 和迁移信息。

记录 ID 由来源标识哈希生成。导出不包含草稿、guest token、房间号或对手昵称。清除只影响统计库，不删除当前单人/多人恢复凭据；`clearedAt` 阻止清除前的重放终态重新写回历史。

## 3. 多人契约补充

1. `round.ended.answer` 增加稳定的 `workId`、`workTitle` 和 `workCode`。
2. 房间事件仍只持久化 `answerId`，由 match 绑定的题库快照在投影时水合作品信息。
3. `left` 成员令牌在房间保留期内仅允许读取最终 snapshot；WebSocket 与所有写命令继续拒绝。
4. 主动离房后先读取最终 snapshot 并完成本地归档，再清理 `touhouflandre:multi-room`。

## 4. 实施顺序

1. 本地 schema、迁移、哈希主键、广播同步、导入导出。
2. WS 答案作品字段和离房只读终态恢复。
3. 统一前台有效计时器与单人记录器。
4. 多人事件草稿、round 幂等追加和 match 事务归档。
5. 纯聚合函数、统计面板、图表、分页记录、清除和导入导出。
6. 更新产品与多人设计文档，补齐单元、协议、服务端、组件和 E2E 覆盖。

## 5. 验收矩阵

- 聚合：混合模式、BO3 多 round、平局、弃赛、零分母、P90、跨月/跨年连胜。
- IndexedDB：schema、事件重放幂等、事务归档、清除边界、导入冲突与损坏文件。
- 协议/服务端：答案作品字段、双方视角投影、left 成员只读 snapshot、写权限仍拒绝。
- 页面：模式/日期/赛制筛选，图表 tooltip，分页 `10/25/50`，头像顺序，空状态、同步不完整与确认对话框。
- 浏览器：单人胜负、多人 BO3/再战/离房/断线恢复、清除、导入导出，以及 desktop 与 Pixel 7 布局。
