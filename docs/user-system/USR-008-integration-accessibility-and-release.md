# USR-008：集成、可访问性与发布验收

**类型**：quality / release
**优先级**：P0
**依赖**：USR-003、USR-004、USR-005、USR-006、USR-007
**状态**：not started
**建议标签**：`user-system`, `quality`, `release`

## Problem

用户系统横跨 Next.js 页面、Go API、Postgres、OpenAPI/SQLC 生成物、本地 IndexedDB 和多人 WebSocket。单个功能通过并不代表入口回跳、权限、移动端、数据安全或游客兼容没有回归；目前也没有可以阻止不完整发布的统一证据清单。

## Required outcome

建立并执行跨模块发布闸门，证明总规范中的认证、资料、安全、同步、管理员和多人退出流程在支持的桌面/移动浏览器上闭环；记录生成物、测试、监控和可回滚点。所有检查在实现前保持未勾选，完成时追加证据。

## In scope

- 端到端流程矩阵：个人入口、登录/注册/找回/重置、个人资料/密保/改密、同步冲突、管理员操作、多人账号身份和异常退出。
- 权限与会话回归：普通用户访问管理员地址、停用/冷却、跨设备失效、本人强制下线、秘密字段不展示。
- 320px、桌面宽屏、键盘、读屏、深浅色主题、减少动态效果和错误/等待/确认状态检查。
- OpenAPI/SQLC/前端生成物检查、迁移可重复性、现有单人/游客多人/统计测试回归。
- 观测和运行手册：注册暂停、认证冷却、重置凭据签发/消费、同步失败/过期、强制下线和房间离开异常的指标/日志不含秘密。
- 发布开关、数据库备份/迁移顺序、逐步启用和回滚边界；回滚不得删除账号、UID 或本地统计。

## Out of scope

- 在本 Issue 中补写缺失的业务功能或改变任一前置 Issue 的产品行为。
- 新增账号渠道、批量管理员能力、同步合并、账号注销或重构现有多人协议。

## Likely code areas

- `docs/user-system/release-gate.md`、`docs/user-system/README.md`
- `apps/web/`、`apps/api/`、`contracts/`、`packages/shared/` 的集成测试和生成任务
- `Taskfile.yml`、部署配置和运行手册（仅补充用户系统所需开关/检查）

## Acceptance criteria

- [ ] 发布闸门中的每项检查都有命令、环境、版本和结果证据；未通过项阻止发布，不以口头确认替代。
- [ ] 端到端矩阵覆盖成功、失败、冷却、过期、权限变化、网络中断和未保存确认，且游客现有流程无回归。
- [ ] 桌面/移动端和键盘/读屏检查证明表单、头像浮层、差异预览、管理员列表和确认框没有溢出、遮挡或只靠颜色表达状态。
- [ ] `task check:generated`、`pnpm test`、`pnpm typecheck`、`pnpm build`、API 测试和迁移/契约检查通过；生成物无手工漂移。
- [ ] 运行文档说明注册暂停、冷却/重置凭据、同步失败和房间异常的告警与人工处理；日志/指标抽样不含秘密。
- [ ] 发布前存在可验证的数据库备份和回滚点；关闭用户系统开关可保留游客功能，回滚不删除账号、UID 或本地数据。

## Test plan

- Playwright 多浏览器矩阵和移动 viewport；API/WS 双会话和权限集成测试。
- 全仓库单元/集成测试、生成检查、迁移演练和构建产物审查。
- 安全检查：秘密字段响应扫描、日志抽样、会话撤销、一次性授权重放和冷却绕过尝试。
- 发布前后小流量灰度与回滚演练，记录实际观测指标和偏差。

## Dependencies and follow-ups

所有前置 Issue 必须达到可验收状态。本 Issue 完成后才可将用户系统标记为发布完成；发现业务缺口应回到对应 Issue 或新增有明确依赖的 Issue，不在发布闸门中偷偷实现。
