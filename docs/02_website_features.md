# 功能与架构

本文介绍东方芙一把（TouhouFlandre）的产品范围、页面职责和系统边界，供使用者与贡献者快速了解项目。内容以仓库当前实现为准；未完成能力单独列入路线规划。

## 产品概览

东方芙一把是一款浏览器端东方角色推理游戏。服务端负责选择答案、校验猜测和生成反馈，客户端负责搜索、游玩、会话恢复与结果展示。

项目的设计目标是：

- 无需账号即可完成每日题和随机题；
- 反馈规则稳定、可解释，答案不会发送给进行中的客户端；
- 角色名称与标签适合中文语境，同时保留多语言搜索能力；
- 数据、比较逻辑、API 与界面保持清晰边界，便于社区维护。

| 能力       | 状态   | 说明                                          |
| ---------- | ------ | --------------------------------------------- |
| 每日题     | 可用   | 同一天使用固定题目，支持恢复会话              |
| 随机题     | 可用   | 创建独立随机会话，可重新开始                  |

| 结果分享   | 可用   | 复制无剧透的纯文本摘要                        |
| 本地持久化 | 可用   | Postgres 保存游戏会话，浏览器保存会话标识     |
| 多人房间   | 可用   | 创建/加入房间（6 位房间号）、BO1/3/5/7 赛制、实时竞速、匿名对手矩阵、再来一局；游客身份房间级有效（无排行/无云存档） |

## 页面与路由

| 路由             | 页面职责               |
| ---------------- | ---------------------- |
| `/`              | 品牌首页与主要游戏入口 |
| `/single`        | 游戏模式选择           |

| `/single/random` | 随机题                 |
| `/search`        | 角色题库搜索           |

## 游戏交互

游戏页包含以下区域：

1. 模式与题目标识；
2. 当前猜测次数和会话状态；
3. 带自动建议的角色搜索框；
4. 按提交顺序展示的反馈表格；
5. 游戏结束后的答案与分享操作。

搜索结果仅显示可猜角色。角色搜索页以有界结果集展示匹配项，可在图标与列表视图之间切换，并按罗马字/英文名称或头像编号表达的登场顺序排序。图标视图显示头像、名称、英文名和初登场作品；列表视图显示头像、名称、初登场作品、年份、种族、地点和阵营。视图、排序字段和正倒序保存在 URL 查询参数中，刷新或分享地址后仍能恢复。

游戏输入框使用同一搜索接口，但限制建议数量以保持下拉列表可操作。已提交角色会在当前会话中禁用。客户端不会自行计算反馈，所有判定均采用 API 返回值。

## API

`contracts/openapi/openapi.yaml` 是 HTTP 契约唯一入口。Go 侧使用 oapi-codegen 生成 handler 接口和 DTO，前端使用 openapi-typescript 生成类型并通过 openapi-fetch 调用。

前端默认请求同源 `/api`，由 `apps/web/next.config.ts` rewrites 代理到 `http://127.0.0.1:4000`。若设置 `NEXT_PUBLIC_API_BASE_URL=http://localhost:4000`，浏览器会直连 Go API。

| 方法   | 路径                                                        | 用途                              |
| ------ | ----------------------------------------------------------- | --------------------------------- |
| `GET`  | `/api/health`                                               | 服务健康检查                      |
| `GET`  | `/api/catalog`                                              | 获取内容类型与题库统计            |
| `GET`  | `/api/characters/search?q=&limit=&offset=&sort=&direction=` | 搜索、排序或分页读取可猜角色      |
| `POST` | `/api/puzzles/:mode`                                        | 按已注册模式创建游戏会话          |
| `GET`  | `/api/sessions/:sessionId`                                  | 恢复公开会话状态                  |
| `POST` | `/api/sessions/:sessionId/guess`                            | 提交 `guessId` 并获取更新后的会话 |

进行中的公开会话不包含答案。会话获胜或失败后，API 才返回完整答案数据。

## 仓库结构

```text
apps/
  api/             Go + Echo API、goose 迁移、sqlc 查询和题库 seed
  web/             Next.js App Router 客户端
contracts/
  openapi/         OpenAPI 契约与拆分 schema/path 文件
packages/
  data/            角色、作品数据与 Zod schema
  shared/          前端共享类型、字段、模式、搜索归一化与分享文本
docs/              项目文档
```

`packages/shared` 不依赖浏览器，可独立测试；权威比较、每日题、随机题和会话逻辑位于 Go API。`packages/data` 负责源数据的结构校验。`apps/api` 是答案与会话状态的可信边界，`apps/web` 不应包含隐藏答案选择逻辑。

角色头像地址属于角色数据，由 seed 写入数据库并经搜索、猜测和结算响应返回。服务端从题库快照读取角色数据，按 Go `internal/game` 规则统一生成反馈。

## 状态与存储

- Postgres 保存角色、作品、版本化题库快照、每日题映射、会话和猜测记录。
- 浏览器 `localStorage` 分别保存每日题和随机题的会话标识。
- 刷新页面时，客户端先尝试恢复原会话；会话不存在时再创建新会话。
- 服务端按 `Asia/Shanghai` 自然日创建每日题映射；同一日期一旦创建便不受后续题库变化影响。
- 会话引用创建时的题库快照，题库更新不会改变已开始会话的答案和比较数据。
- 猜测提交使用会话版本进行乐观并发检查，冲突时最多重试两次，避免同时提交覆盖记录。
- 公开会话中的猜测头像由 API 保证完整；持久化记录未包含头像地址时，API 会从会话绑定的题库快照解析。

本地存储只用于恢复入口，不作为服务端游戏状态的替代品。

## 兼容性与无障碍

客户端面向支持 ES modules、Fetch API、History API 和 Clipboard API 的现代浏览器。界面应满足以下基础要求：

- 所有主要操作可通过键盘完成；
- 图标按钮具备可访问名称或提示；
- 状态不只依赖颜色表达；
- 小屏幕可横向查看反馈表格；
- 系统启用“减少动态效果”时停用非必要动画。

1. 完善题库校验、来源记录和数据纠错流程；
2. 增加本地统计与猜测分布；
3. 引入账号体系和跨设备同步；
4. 实现多人房间、实时状态与排名；
5. 提供受权限保护的内容管理工具。

路线规划不构成发布承诺，具体范围以版本里程碑和 issue 为准。
