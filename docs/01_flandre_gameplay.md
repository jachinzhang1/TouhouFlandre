# 游戏规则

本文说明东方芙一把（TouhouFlandre）的公开玩法、反馈含义与结算规则。实现细节和接口约定分别见[功能与架构](./02_website_features.md)和[本地开发指南](./04_local_demo_development.md)。

## 游戏目标

东方芙一把是一款以《东方 Project》角色为题库的推理游戏。每局游戏会从当前答案池中选出一名隐藏角色。玩家提交角色后，系统逐项比较该角色与答案的属性，玩家据此排除候选并继续猜测。

一局游戏按以下流程进行：

1. 系统创建题目并确定隐藏角色。
2. 玩家通过名称、别名或初登场作品搜索候选角色。
3. 玩家选择并提交一名尚未猜过的角色。
4. 系统返回各字段的比较结果。
5. 玩家猜中答案，或用完本局的猜测次数。

## 游戏模式

### 每日题

同一自然日内的每日题使用固定答案，便于玩家比较结果。浏览器会保存当前会话标识，刷新页面后可继续游戏。每日题日期由服务端按 `Asia/Shanghai` 时区确定；当天映射创建后，即使题库随后更新也不会改变。

### 随机题

每局从已启用的答案池中随机选择角色。玩家可随时重新开始，新的会话与每日题记录相互独立。

### 多人模式

多人模式已列入项目路线，但当前版本尚未提供实时房间与对战功能。相关入口仅用于展示未来页面结构，不计入现有可玩范围。

## 比较字段

当前版本启用六个公开字段：

| 字段       | 类型 | 比较方式                                   |
| ---------- | ---- | ------------------------------------------ |
| 初登场作品 | 层级 | 作品相同为完全匹配；媒介类型相同为部分匹配 |
| 初登场年份 | 数值 | 相同为完全匹配；否则箭头指向答案所在年份   |
| 种族       | 多值 | 集合相同、存在交集或无交集                 |
| 阵营       | 多值 | 集合相同、存在交集或无交集                 |
| 主要地点   | 多值 | 集合相同、存在交集或无交集                 |
| 头发颜色   | 多值 | 集合相同、存在交集或无交集                 |

能力、角色定位等资料可以保存在题库中，但不会参与当前版本的猜测反馈。

## 反馈含义

| 标记 | 含义     | 说明                                     |
| ---- | -------- | ---------------------------------------- |
| `O`  | 完全匹配 | 猜测值与答案值一致                       |
| `~`  | 部分匹配 | 多值字段存在交集，或层级字段属于同一类别 |
| `X`  | 不匹配   | 两者没有可用于缩小范围的重合             |
| `↑`  | 答案更晚 | 答案的初登场年份晚于猜测角色             |
| `↓`  | 答案更早 | 答案的初登场年份早于猜测角色             |
| `?`  | 未知     | 数据不足，系统不据此作出判断             |

对于多值字段，只有两个标准化集合完全相同时才算完全匹配。任何非空交集均为部分匹配。例如，猜测角色的种族为“人类、魔法使”，答案为“魔法使”时，结果为部分匹配。

## 胜负与会话

- 提交的角色与隐藏答案相同时，游戏立即获胜。
- 达到本局最大猜测次数仍未命中时，游戏结束并公布答案。
- 已结束的会话不再接受新的猜测。
- 同一角色在同一局中不能重复提交。
- 游戏结束后可复制不包含答案名称的分享文本。

当前默认上限为 8 次猜测。该值属于服务端会话配置，前端只展示服务端返回的结果。

## 搜索规则

搜索支持以下信息：

- 简体中文、日文、英文与罗马字名称；
- 题库中登记的常用别名；
- 初登场作品名称、简称与作品编号。

猜测必须从搜索结果中选择，不能提交任意文本。此约束用于消除翻译和拼写差异，并保证每次猜测都能关联到一条经过校验的角色数据。

## 分享格式

分享文本包含题目标识、完成状态、字段顺序、每次猜测的反馈摘要和站点地址，不包含答案名称。例如：

```text
TouhouFlandre 每日题 2026-08-03
4/8
初登场作品 初登场年份 种族 阵营 地点 头发颜色
X X ~ X O X
X ~ ~ X O X
~ O O X O ~
O O O O O O
https://example.com
```

## 公平性原则

- 公开字段必须采用稳定、可解释的判定标准。
- 争议属性应记录来源；无法可靠判断时使用未知状态。
- 每个启用为答案的角色必须具备全部核心字段。
- 题库调整不应改变已经开始的会话结果。
- 分享内容不得在游戏结束前泄露答案。

有关字段来源、标准化方式和纠错流程，见[东方内容与数据规范](./03_touhou_integration.md)。
